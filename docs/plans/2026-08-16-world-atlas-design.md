# 世界地図版(せかいの ちず)— 統合方針と分岐設計

日付: 2026-08-16
状態: **計画のみ(未実装)**。方向性の合意を記録する文書。
実装着手前に §4 の未解決課題を決めること。

## 1. 結論: 別アプリにせず、同一アプリに統合する

ただし前提条件がある。**世界版が「今と同じ日本の子ども向け(日本語 UI・
ひらがな中心)」である限り**、の統合判断。海外市場向けにローカライズした
世界版を作る場合は別プロダクトであり、その時は別アプリとして設計し直す
(CLAUDE.md §1「英訳ブランドで英語アプリに見せない」と混ざるため)。

### 理由

| # | 理由 | 補足 |
| --- | --- | --- |
| 1 | **別アプリだと既存ユーザーに届ける手段がない** | Kids カテゴリの「アプリ外リンクを作らない・ペアレンタルゲートを置かない」制約(CLAUDE.md §1, §8)により、既存アプリ内から新アプリへの導線が原理的に作れない。世界版はストア検索だけでゼロから発見されることになる。同一アプリならアップデートで全員に届く |
| 2 | **「ちずはかせ」は日本地図限定の名前ではない** | 「にほんの ちず」と「せかいの ちず」の 2 冊を持つ博士、という拡張は自然。英語ストア表記のサブタイトル(*Japan Map Quiz for Kids*)は公開後でも変更できる(固定なのは bundle ID のみ) |
| 3 | **継続動機の設計と噛み合う** | マイマップとカードの積み上げが継続の軸。その積み上げがある場所に新しい地図が増える方が強い。ずかんに「せかいのカード」の空きマスが現れること自体が動機になる |
| 4 | **コード共有が最大化される** | 地図描画・ヒットテスト・ZoomPan・GameRules・カード抽選・セーブのマイグレーション機構をすべて流用。別アプリはストア運用(スクショ・審査・プライバシーラベル・レビュー獲得)が恒久的に 2 倍になる |

## 2. 分岐設計: タイトル 1 カ所だけに置く

**タイトル画面を「アルバムのページ」として にほん / せかい の 2 ページにし、
そこで選んだ「ちずちょう(アトラス)」を下の全画面に引き回す。**
それより下の画面には二度と分岐を作らない。

```
タイトル(ページ式: にほんの ちず ⇄ せかいの ちず)★分岐はここだけ
 ├ あそぶ → ステージせんたく(そのちずちょうのステージ一覧)
 │            └ モード切替(ちずでさがす / なまえをあてる)← 今のまま
 ├ おぼえたタリー → マイマップ(そのちずちょうの地図)
 └ カードタリー → ずかん(そのちずちょうのカード)
```

### なぜタイトルか

- **タイトルアートの設計がそのまま世界に効く。** 現在のタイトルは
  「自分の進捗(習熟色の日本地図)が飾ってある」画面(`TitleView.miniMap`)。
  世界ページも同じ構造(世界のシルエットが緑に染まっていく + タリー)に
  すれば、ページをめくった瞬間に「こっちの本はまだ白い」が伝わる
- **分岐を 1 カ所にしないと、5 歳児がトグルの状態を追えない。**
  ステージ選択やずかんの中に切替を置くと、同じ切替が 3 画面に散らばり、
  「いま自分がどっちの本にいるか」を画面ごとに確認させることになる。
  CLAUDE.md §5「マイマップを 2 面に分けると 5 歳児には把握できない」と
  同じ理屈で、**面を分けるなら本ごと分け、本の中では一切分岐させない**
- **既存リストへの混載は破綻する。** ぜんこくチャレンジの隣にヨーロッパが
  並ぶと縮尺の世界観が混ざり、マイマップが 1 枚の地図で表現できなくなる

### UI の要点

- スワイプだけだと子どもには見つからない。**ページ端に見えるボタン
  (「せかいの ちずへ →」等)またはタブを置く**
- 前回開いていたページを記憶し、次回起動はそのページから始める
- 設定(⚙️)・効果音・音楽は全体共有のまま(ページに属さない)

### 分岐を置いてはいけない場所

- **クイズモードの階層。** ちずでさがす / なまえをあてる は「出題の向き」で
  アトラスと直交。今の位置(ステージ選択上)のまま両アトラス共通
- **マイマップ・ずかんの内部。** どっちの本のものを見るかはタイトルで
  決まっている。本の切替はタイトルに戻る(ページをめくる)ことでやる

## 3. 実装方針

- **`Atlas`(ちずちょう)を 1 つの値にする**: mapData + stages + cards +
  音声入力語彙の束。`AppState` が japan / world の 2 つを持つ
- **`RootView.Route` の各ケースに atlas を足す**(または選択中 atlas を
  `RootView` の `@State` に置く。`quizMode` と同型のセッション状態)
- **View はアトラス非依存のまま保つ。** `PrefectureMapView` /
  `PrefectureGeometry` / `ZoomPan` は rings と codes しか見ていないので、
  世界データを食わせるだけで動く。分岐はデータ(Atlas)に閉じ込める
- **日本ハードコードの置換箇所**: `Stage.all`、タイトルの `Array(1...47)` と
  タリーの `47`、`MasteryStyle.appearance(for:save:)` の習熟参照、
  `VoiceInputService` の語彙(47 県名 → アトラスごとの語彙)
- **SaveData v6 でアトラス名前空間化**: 現行の `mastery` / `cards` /
  `rainbow` / `streaks` / `records` を `atlases["japan"]` へ移す
  マイグレーションを `SaveData.init(from:)` に足す(v1→v5 と同じ路線)。
  カード ID「01-1」はアトラス内で閉じるので世界カードと衝突しない。
  `settings` は全体共有のまま
- 世界の国コードはアトラス内で完結する Int(ISO 3166-1 numeric 等)。
  日本の県コード 1–47 とは名前空間が分かれるので衝突しない

## 4. 未解決の課題(実装前に決める)

分岐設計より重い判断が 2 つある(★)。

- ★ **タップ判定と収録単位。** 香川問題が世界では桁違いになる
  (シンガポール、バチカン、カリブ・太平洋の島嶼国)。大陸ステージ +
  ズーム前提とし、マイクロ国家の扱い(除外 / 地域まとめ / インセット)を
  先に決める。「せかいチャレンジ」(約 200 カ国を 1 画面)は 5〜9 歳には
  成立しない — 全国チャレンジ相当を世界でどう定義するか
- ★ **収録範囲とカード制作量。** 全カ国 × 3 枚 = 約 600 枚は非現実的。
  主要国に絞る / 国 × 1 枚にする等、コンテンツ量の判断が最大のコスト
- **世界地図データのパイプライン。** Natural Earth 等 → `build_map_data.py`
  の一般化。出典表記の追加(現在は国土地理院のみ)。沖縄インセット相当の
  処理(遠隔領土・アラスカ等)をどうするか
- **国名のひらがな表記。** 「あめりか」「べとなむ」等の表記決め。読み上げ・
  音声入力の表記ゆれ吸収(「あめりか」「あめりかがっしゅうこく」)も同時に
- **記録全削除のスコープ。** アトラス単位か全体一括か。誤操作を考えると
  「全体一括 + 2 段階確認」のままを推奨
