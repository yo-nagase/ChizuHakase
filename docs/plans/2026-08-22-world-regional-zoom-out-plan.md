# 世界の地方ステージの縮小(ズームアウト)計画

日付: 2026-08-22
状態: 実装と同時に記録。

---

## 1. 何を作るか

世界の地方ステージ(にしヨーロッパ等)の平面地図を、**既存と同じ操作
(ピンチイン / 長押し→下スライド)で fit より小さく縮小できる**ようにする。
縮小すると周りの国と大陸が現れ、「この地方は世界のどのあたりか」を
その場で確かめられる。

- 床はデータから導く: **全収録国の枠(せかいチャレンジと同じ
  `frameBbox ?? bbox` の和)が枠内に収まる縮小率**まで。
  ズーム上限 `GameRules.challengeFlatMaxZoom`(P9)の鏡像で、
  `min(w/cw, h/ch)` はフレーム比によらず「全世界が見える」を保証する
  (フィット比の商 `k_world/k_stage ≥ min(w/cw, h/ch)` が任意の W×H で成立)
- **縮小中はパンしない。** `ZoomPan.clamp(offset:)` は scale ≤ 1 で
  offset を 0 に畳む既存挙動のまま — 地方が常に中央にいるので、
  「どのあたりか」の答えが画面の外に逃げない・地図を見失わない
- 「もとの おおきさ」チップは縮小中も出す。問題が進んだら fit へ戻る
  (拡大と同じ既存のリセット)
- 日本の地方ステージ・両チャレンジ・マイマップ・カード拡大は床 1 のまま
  1 ピクセルも動かさない(日本の地方は周辺県を描いておらず、
  縮小しても偽の海が広がるだけ。チャレンジは既に全世界が枠内)

## 2. 変更点

| 場所 | 変更 |
| --- | --- |
| `GameRules` | `regionalFlatMinZoom(bookSpan:stageSpan:)` を追加(純関数・テスト付き) |
| `Stage` | `flatMinZoom`(既定 1)を追加 — `flatMaxZoom` と対になる「ステージが運ぶ値」 |
| `Atlas.world(from:)` | 地方 18 面に床を焼き込む。枠の測り方は上限と同じ `frameBbox ?? bbox` |
| `ZoomPan` | `clamp(scale:max:min:)` / `scale(_:liftedBy:max:min:)` に床引数、`isZoomedOut`、modifier と `zoomPan()` に `minScale` |
| `PrefectureMapView` | `minZoom` を受け、**床ぶんのオーバースキャンを常時描画・クリップも同率で拡張**。線幅・タップ許容・コンボ印は縮小側でもガラス上で等寸(`max(zoom, 1)` → 生の zoom で割る) |
| `QuizView` | `zoomPan` と地図へ床を渡す。リセットチップの条件に縮小を足す |

## 3. 判断の記録

- **オーバースキャンは床固定で常時描く。** `zoom` 状態はジェスチャ終了まで
  動かない(`ZoomPanModifier` の live 値は内部の GestureState)ので、
  現在値で間引くとピンチ中に空白の海が見え、指を離した瞬間に大陸が
  ポップインする。世界の地方ステージは文脈レイヤ(周辺国)を既に
  1 本のパスで描いており、全世界ぶん描いてもせかいチャレンジより軽い
- **タップは縮小中も生きる。** 許容 22pt はガラス基準のまま
  (`tolerance / zoom`)— せかいチャレンジの fit 時と同じ密度・同じ規則で、
  縮小したら急に答えにくくなる/広い網になる、のどちらも起こさない
- **ヒントチップ(👆)は地方ステージに増やさない。** 既存の判断
  (地方は形が指サイズで、毎問の家具になる)のまま。ピンチインは
  拡大と対称の操作で、教えるべき隠し技ではない
