# GitHub Issue の起票とIssue対応PR

## 前提

issue は**コールドスタートの読み手（AI エージェント・将来の自分・他の開発者）に投げる作業単位**。読み手はこの会話を知らない。会話で分かったことは本文に全部書く。

## 手順

1. **調査** — 対象をコードで確認してから書く。`file:line` は実在を確認した行だけ書く（コメントや過去ドキュメントの記述も現状と突き合わせる）。
2. **重複確認** — `gh issue list --state all --search "<キーワード>"`。似た issue があれば新規ではなくそちらへの追記を提案。
3. **ラベル** — `gh label list` で実在するものだけ。無ければ付けない。新規ラベル作成は頼まれたときだけ。
4. **スコープが割れたら書く前に聞く。** 読み方が複数あって**別の issue になる**なら、AskUserQuestion でユーザーに確認する。実測: 同じ依頼文を渡した 2 つのエージェントが、正反対のスコープに決め打ちした issue をそれぞれ書いた。どちらも書けてしまうときは、どちらかを選ぶのではなく聞く。
   - 聞けない状況（サブエージェント等）では、最終出力でスコープの分岐を明示して判断を返す。決め打ちで起票しない。
5. **本文** — 言語はリポジトリの慣行に合わせる（README・既存ドキュメントの言語）。型:
   - **背景 / 現状**（検証済み `file:line` 参照つき）
   - **やること / やらないこと**（スコープ外を明示）
   - **完了条件**（チェックボックス）
   - **判断が必要な点** — 自分で決めなかった実装判断はここに残す。issue は作業単位であって設計書ではない。設計が要る規模なら、先に設計ドキュメントを書くことを提案（置き場はリポジトリの慣行に従う）
   - CLAUDE.md 等にプロジェクトの絶対制約が明記されている場合、それに触れうる内容ならその旨を本文に書く
6. **承認 → 作成。** 本文を scratchpad のファイルに書き、タイトル・ラベル・本文をユーザーに見せて承認を得てから:
   ```bash
   gh issue create --title "<タイトル>" --label <実在ラベル> --body-file <ファイル>
   ```
   `--body-file` を使う（長文をシェル引数に埋めない）。承認前に create を実行しない。
7. **作成後** — issue の URL を報告する。

## Issue対応のPull Request

ユーザーがIssueの実装とPR作成を依頼した場合は、長期ブランチへ直接積まず、
Issue専用ブランチからPRを出す。

1. `git status`、現在ブランチ、リモートとの差分を確認し、ユーザーの未コミット変更を保持する。
2. PRの正しいベースから `feature/issue-<番号>-<短い内容>` 形式のブランチを作る。
   例: `feature/issue-10-world-landmarks`。既存のIssueコミットを移す場合も、
   元の長期ブランチへコミットを残さない。
3. Issue対応だけをコミットし、専用ブランチをpushする。
4. PRのタイトルと本文にIssue番号を明記する。
   - 既定ブランチ宛て: 本文に `Closes #<番号>` を入れ、マージ時に自動クローズさせる。
   - 非既定ブランチ宛ての積み上げPR: Issueへの相互参照を入れ、最終的な既定ブランチ宛てPRで
     `Closes #<番号>` を使うか、マージ後に手動で閉じる。非既定ブランチへのマージでは
     GitHubの自動クローズが動かないことを報告する。
5. 作成後にhead/baseブランチとIssue側のcross-referenceを確認し、PR URLを報告する。

PR作成・pushなどGitHubへの書き込みは、ユーザーがPR作成を依頼したときだけ行う。

## よくある間違い

| 間違い | 正 |
| --- | --- |
| 曖昧なスコープを推測で確定して起票 | 別の issue になる分岐は先に聞く（手順 4） |
| 実装判断まで issue で固定 | 「判断が必要な点」に落とす |
| 存在しないラベルを指定（create が失敗） | `gh label list` で確認済みのものだけ |
| 下書きを見せずに create | 承認後のみ。issue は外向きの成果物 |
| 未検証の file:line・「〜のはず」を本文に書く | 実在確認した事実だけ。推測は推測と書く |
| 長期ブランチへIssueのコミットを直接push | Issue専用の `feature/issue-<番号>-<内容>` からPR |
| PR本文にIssue番号がなく、対応関係が残らない | `Closes #N` または相互参照を本文へ入れて確認 |
| 非既定ブランチ宛てでも自動クローズされると案内 | 最終の既定ブランチPRで閉じるか、手動クローズを明示 |
